# Мой кабинет — Android-прототип v0.2.0 (GitHub Updates)

Простой проект на Python / Flet 1.0.5 / SQLite. Работает на Windows через PyCharm и собирается в Android APK. **Первая функция после регистрации и ЛК — проверка обновлений через публичные GitHub Releases.**

## Изменения v0.2.0

- Экран **«Обновление приложения»** доступен из ЛК и с экрана входа.
- Кнопка **«Проверить обновления»** запрашивает последний стабильный выпуск GitHub Releases (есть таймаут и сообщения об ошибках).
- Сравнивает версии правильно: `0.10.0` новее `0.9.0`.
- Если доступен новый выпуск, показывает заголовок, описание и **«Скачать APK обновления»**.
- Ссылка открывает скачивание APK во внешнем браузере телефона. **Установку подтверждает сам пользователь в Android.**
- Ни регистрация, ни база пользователей не заменены; SQLite остаётся локальной на устройстве.

Важно: это **обновление Android APK**, не загрузка и выполнение Python-файлов по сети. Один `git push` в GitHub *не* обновит код приложения: нужна новая сборка **APK**, опубликованная в GitHub **Release**. Мы не делаем опасного запуска неподписанного кода из интернета.

## 1. Запуск на компьютере

1. Распакуйте ZIP и откройте `android_login_demo` в PyCharm.
2. Запустите `install_windows.bat` (в первый раз) и затем `run_windows.bat`.
3. Зарегистрируйте пользователя, войдите в ЛК, откройте **«Проверить обновления»**.
4. Пока не создан публичный Release в GitHub, проверка выдаст понятное сообщение, что выпуск пока не найден. Это нормально.

Python 3.10+ и интернет для первичной установки пакетов нужны; Android Studio отдельно не обязательно.

## 2. Создайте GitHub-репозиторий

В `src/update_config.py` указаны:

```python
APP_VERSION = "0.2.0"
GITHUB_OWNER = "hermaer"
GITHUB_REPOSITORY = "android-login-demo"
```

Это **пример конфигурации**, а не ссылка на уже созданный релиз. Создайте **публичный** репозиторий `android-login-demo` в GitHub-аккаунте `hermaer` или замените `GITHUB_OWNER` и `GITHUB_REPOSITORY` на ваши значения **до сборки APK**. Приватный репозиторий не поддерживается этой демонстрацией: не зашивайте в мобильное приложение GitHub-токен.

Исходники могут находиться в таком же репозитории, но приложение смотрит **только GitHub Releases**, а не коммиты или архив ZIP кода.

## 3. Зачем нужна одна и та же подпись APK

**Критично для сохранения пользователей:** Android обновляет приложение поверх установленного только при неизменном `bundle_id` и совпадении сертификата подписи APK. Если подпись не совпадёт, Android откажет в обновлении. Удаление старого приложения ради установки нового обычно удалит локальную базу SQLite.

В `pyproject.toml` текущий `bundle_id`: `com.example.simplecabinet`. Если первая версия уже установлена, **не меняйте этот идентификатор**. Для будущего публичного продукта лучше выбрать ваш собственный ID до первого распространения приложения.

Перед публикацией первой распространяемой APK создайте постоянный ключ, если его ещё нет. Нужен `keytool` из Java JDK (Flet скачает JDK при первой сборке; если `keytool` не найден, укажите полный путь к его `.exe`):

```powershell
keytool -genkeypair -v -keystore android-release-key.jks -alias upload -keyalg RSA -keysize 3072 -validity 10000
```

Программа попросит пароль и данные сертификата. Не публикуйте JKS-файл и пароль — **навсегда сохраните ключ и резервную копию в безопасном месте**. Если он потеряется, дальнейшие обновления текущей установки будут невозможны.

Скопируйте `signing.local.example.bat` в `signing.local.bat`. Укажите там **абсолютный путь к JKS** и пароль, которые задали. Файл исключён из Git через `.gitignore`, но всё равно не загружайте его на GitHub.

> Если v0.1.0 уже установлена без постоянного ключа, v0.2.0 с новым ключом может не установиться поверх неё. В таком случае **перед удалением старой версии убедитесь, что вам не нужна её локальная база**: при удалении данные могут пропасть. После первой установки с новым постоянным ключом будущие обновления будут работать поверх неё.

## 4. Соберите и опубликуйте первую версию

1. Запустите `build_apk_windows.bat`. Этот скрипт подхватит настройки подписи из `signing.local.bat`, если они есть.
2. Дождитесь завершения; APK будет в `build/apk/`. При первой сборке Flet может скачать Android SDK, Flutter SDK и JDK.
3. В GitHub откройте ваш репозиторий → **Releases** → **Draft a new release**.
4. Создайте тег **`v0.2.0`**, заголовок `Версия 0.2.0` и описание изменений.
5. Прикрепите **готовый `.apk`**, а **не ZIP с исходниками**. Если можно, загружайте **один универсальный APK**, без нескольких вариантов для разных процессоров.
6. Опубликуйте Release (**Publish release**) и установите этот APK на телефон.

Проверка внутри версии 0.2.0 должна показать, что установлена актуальная версия. Если выпуск ещё не существует, будет сообщение об отсутствии Release.

## 5. Проверьте реальное обновление на телефоне

Измените код приложения в PyCharm (например, надпись «Личный кабинет»).

Затем в терминале корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe set_version.py 0.3.0
```

Скрипт одновременно увеличит `project.version`, `APP_VERSION` и Android `build_number` (2 → 3). Не забудьте сохранить изменения в Git (`git add`, `git commit`, `git push`), **но этого недостаточно**.

Далее:

1. Снова запустите `build_apk_windows.bat` **с той же подписью**.
2. Создайте в GitHub Releases новый стабильный выпуск с тегом **`v0.3.0`** и прикрепите новый APK.
3. На телефоне откройте **старую версию 0.2.0** → **«Проверить обновления»**.
4. Появится «Доступно обновление: 0.3.0» и кнопка **«Скачать APK обновления»**.
5. После скачивания откройте APK в загрузках телефона и подтвердите установку поверх старой версии. Возможно, потребуется дать браузеру или файловому менеджеру разрешение на установку из этого источника.
6. Откройте приложение: изменения появились, локальный пользователь должен остаться, если вы не удаляли приложение и не меняли его ID/подпись/расположение данных.

При проверке на Windows та же кнопка скачает Android APK через браузер: **устанавливать его нужно на телефоне**.

## 6. Про ограничения и следующий этап

- **Это не бесшовное автообновление:** приложение проверяет новую версию и открывает загрузку; Android-инсталляцию запускает и подтверждает пользователь. Автоматическую установку APK без участия пользователя обычное приложение не выполняет.
- Для этой версии **публичный GitHub Release** необходим; GitHub может быть недоступен по сети или ограничить запросы.
- `SQLite` хранит аккаунты **локально на каждом устройстве**. Для общего аккаунта, синхронизации, баланса, заявок и т.п. понадобится API + серверная база данных.
- Исходники и APK перед релизом должны проходить проверку: скачивайте сборки только со своего доверенного репозитория.

## Структура проекта

```text
android_login_demo/
├── pyproject.toml              # версия и идентификатор Android-приложения
├── src/
│   ├── main.py                 # вход, регистрация, ЛК, экран обновления
│   ├── database.py             # пользователи и SQLite
│   ├── update_config.py        # версия + GitHub-репозиторий
│   ├── updater.py              # проверка GitHub Releases
│   └── assets/icon.png
├── tests/
│   ├── test_database.py
│   └── test_updater.py
├── set_version.py              # обновление версии сразу в конфигурациях
├── signing.local.example.bat   # шаблон настроек подписи (без секретов)
├── install_windows.bat
├── run_windows.bat
└── build_apk_windows.bat
```

Тесты без установки Flet: `python -m unittest discover -s tests -v`.

### Если приложение пока не запускается

Не запускайте BAT прямо из архива. Все `.bat` в проекте используют Windows `CRLF` и латинские символы в командах. Распакуйте проект в обычную папку, затем сначала `install_windows.bat`, затем `run_windows.bat`.
