# Мой кабинет — версия 0.4.0: «Запомнить меня»

Android / Windows, **Python 3.10+ · Flet 1.0.5 · SQLite**. Обновление добавляет сохранение авторизации после повторного запуска приложения. Сохраняет проверку GitHub Releases, регистрацию, ЛК и выход.

## Изменения 0.4.0

- Галочка **«Запомнить меня»** на форме входа (по умолчанию выключена).
- Если включить её и войти по email/паролю, при следующем запуске откроется **личный кабинет без ввода пароля**.
- Имя профиля и email уже хранятся в SQLite; после выхода оставляем только email в поле входа.
- **Пароль никогда не сохраняется как текст.** Вместо него сохраняется случайный токен (256 бит) в нативном защищённом хранилище: Android Keystore / Windows Credential Manager через `flet-secure-storage==1.0.5`. SQLite хранит **только SHA-256 хеш** токена.
- Срок сохранённого входа — **90 дней**; после этого нужен обычный вход. Выход из аккаунта отменяет сохранённый вход.
- При входе без галочки сохранённая сессия сбрасывается.
- Таблица `remembered_sessions` создаётся миграцией `CREATE TABLE IF NOT EXISTS`. Существующие аккаунты в `users.sqlite3` **не удаляются**.
- Версия для GitHub: **0.4.0**, номер Android-сборки: **4**. Идентификатор `com.example.simplecabinet` не менялся.

> Это прототип **локальных аккаунтов**, не серверная авторизация и не синхронизация между телефонами. На другом устройстве будет другая база пользователей.

## Рекомендуемый способ обновления текущего Git-проекта

Если у тебя уже есть локальный репозиторий `android-login-demo` с **версией 0.3.0**, **не распаковывай ZIP поверх него**. Используй `android_login_demo_v0_4_0_remember_me.patch` из комплекта, чтобы оставить `.git/`, `.venv/`, базу, а также локальные ключи подписи на месте.

1. Скопируй `android_login_demo_v0_4_0_remember_me.patch` в корень проекта — рядом с `pyproject.toml`.
2. Открой Git Bash в корне проекта и выполни:

   ```bash
   git status
   git apply --check android_login_demo_v0_4_0_remember_me.patch
   git apply android_login_demo_v0_4_0_remember_me.patch
   ```

3. Добавь новый Python-пакет для безопасного хранения ключа. В Git Bash:

   ```bash
   ./.venv/Scripts/python.exe -m pip install "flet-secure-storage==1.0.5"
   ```

   Или повторно запусти `install_windows.bat` (он обновлён).

4. Для проверки на Windows запусти `run_windows.bat`.
5. Проверь тесты:

   ```bash
   ./.venv/Scripts/python.exe -m unittest discover -s tests -v
   ```

6. Создай коммит и отправь код:

   ```bash
   git add pyproject.toml install_windows.bat README.md src tests
   git commit -m "Add remember me login v0.4.0"
   git push origin main
   ```

7. Собери APK с **тем же ключом подписи**, что и `v0.3.0`, через `build_apk_windows.bat`. В GitHub → Releases создай `v0.4.0`, прикрепи **APK**, опубликуй. На телефоне с `v0.3.0` нажми «Проверить обновления» и скачай новую сборку.

**Важно:** если `git apply --check` не проходит, **не применяй патч принудительно**. Покажи ошибку и текущий `git status`. Возможно, в исходники уже вносились изменения. Не делай `git reset --hard`, не удаляй базу и не удаляй старое приложение.

## Как проверить на телефоне

1. Сначала убедись, что после обновления до `v0.4.0` прежний пользователь остался: войди с его email и паролем.
2. Отметь **«Запомнить меня»** и нажми «Войти».
3. Полностью закрой приложение (через список недавних) и открой снова: сразу должен появиться личный кабинет.
4. Нажми **«Выйти из аккаунта»**. Должна появиться форма входа, где email уже заполнен; пароль пустой.
5. Перезапусти приложение: должен оставаться экран входа, а не личный кабинет.
6. Войди с выключенной галочкой; после перезапуска приложение снова покажет экран входа.

### Сборка и данные

Для обновления **поверх установленного APK** должны совпадать `bundle_id` и сертификат подписи. Нельзя терять `signing.local.bat` и `.jks` ключ. Не загружай их в GitHub.

`FLET_APP_STORAGE_DATA` используется для SQLite, а Android сохраняет этот каталог при корректном обновлении приложения. **Удаление приложения** удалит локальную базу; «Выйти из аккаунта» базу не удаляет.

В новой версии используются защищённые системные ключи Keystore. После восстановления резервной копии на другой телефон ключ автоматического входа может быть недоступен: потребуется войти вручную. Это не влияет на проверку обычного пароля.

Документация Flet: https://flet.dev/docs/services/securestorage/ и https://flet.dev/docs/cookbook/read-and-write-files/
